1. Берёт текущий asyncio-цикл FastAPI и отдаёт его MQTT-сервису. Без этого paho не сможет запускать async def обработчики.
2. Говорит MQTT: если с робота пришёл кадр CloudTTSRequest, вызови handle_payload (синтез + ответ с аудио).
3. Регистрирует «мозг» робота: handshake модулей, расписание, первый state.
4. В памяти ставит cloud_tts=1 (и puppet, если включено). На робота это уедет позже, при бутстрапе.
5. mqtt_service.connect() — соединение с брокером и запуск фонового потока paho.
6. yield — приложение работает (Swagger, /tts/speak, MQTT-сообщения).
7. При shutdown — disconnect().

Путь POST /tts/speak — кто создаёт id
Вы
  POST /tts/speak  {"text": "Привет!"}     ← event_id здесь нет
        │
        ▼
FastAPI → telehealth.speak_line
        │
        │  MQTT JSON, без event_id:
        │  PLAY_OUTPUT { output: { text, markup } }
        ▼
Робот
        │  сам решает озвучить строку
        │  сам собирает CloudTTSRequest
        │  event_id = то, что поставила ПРОШИВКА
        │    (на PLAY_OUTPUT это почти всегда "")
        ▼
  CloudTTSRequest { markup: "Привет!", event_id: "", chunk_num: 0 }
        │
        ▼
Сервис копирует event_id КАК ЕСТЬ (даже пустую строку)
        │  OpenAI TTS
        ▼
  CloudTTSResponse { audio, event_id: "", chunk_num: 0 }
        │
        ▼
Робот: "я жду event_id='' ? да" → играет


После одного успешно сыгранного cloud-TTS в TELEHEALTH с event_id='' прошивка больше
 не выводит на динамик следующие такие же ответы, хотя продолжает их запрашивать. Сервис 
 отвечает правильно. Баг — в незакрытом output slot и/или в дедупе пустого id на пути PLAY_OUTPUT.
